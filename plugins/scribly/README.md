# Scribly local plugin

This repository package contains no credentials. Installing it alone does not grant access to a notebook.

In the Windows Scribly app, open Settings > Accounts & Advanced > Codex integration. Select folders (or unfiled), choose read-only or writing access, save the settings, and enable the connection. Use **Install Codex plugin** to create a paired, current-user installation with its own local endpoint and credential. Refresh/restart Codex and install Scribly from the **Scribly Local** source if the client does not install local sources automatically. Begin a fresh chat and ask Codex to check Scribly's connection.

The generated private package contains the paired connection credential and is restricted to the current Windows user. Do not share, commit, or publish that installed package. The source package here is the distributable template. Revoke access in Scribly to invalidate the credential, including copies in a Codex cache. Disable the integration to close the listener. Removing the plugin does not remove notes.

The paired installation uses the [Codex compatibility layout](https://developers.openai.com/plugins/build/plugins): `.codex-plugin/plugin.json`, `.mcp.json` with `http_headers`, and `skills/`. This format was verified with Codex's native MCP client. The repository also contains portable templates, but its installer copies only the compatibility files because this installed Codex build does not forward portable header credentials. No adapter process is involved.

After changing the port or re-pairing revoked access, remove the cached Scribly plugin in Codex and install it again from the refreshed local source. Restarting a chat alone does not update a cached credential.

Scribly must be running. Port changes require reinstalling the connection metadata. Ordinary notes and read-only meeting transcripts/summaries in selected folders are available. Search/list/read use the current confirmed transcript and displayed summary, including edited summary text and action completion. Recordings and meeting editing/generation controls are unavailable; all linked notes require their own folder authorization. This requires Scribly 1.5.2 and bundled plugin 0.1.2 or newer. Writes use revision checks and durable operation receipts; committed receipts expire after 30 days. Unresolved receipts remain available for draft recovery. Use the same UUID and arguments to reconcile/retry a request, and check its receipt after timeout.

New prose uses semantic HTML through `format: "html"` on `create_note` and `append_note`, with headings and real lists inheriting Scribly's document styles. `replace_note_text` also supports formatted replacement of a unique run of complete top-level text blocks, so an existing plain section can be repaired without appending duplicates. Annotated blocks, links and embedded content remain protected from structural replacement; literal passage edits preserve surrounding marks and inline boundaries. Reads report `section_heading_level` and accept `expected_version` between pages. Folder listings count readable ordinary and meeting notes, identify the meeting subset and distinguish unavailable active boards/templates; status reports write formats and limits. Literal text remains supported through `format: "text"` or an omitted format. This requires the updated Scribly app; use **Install Codex plugin** to refresh its bundled instructions and refresh/reinstall the cached plugin in Codex. Existing sections are only reformatted through an explicit edit.

The server is embedded in Scribly's Rust process, uses authenticated loopback Streamable HTTP, and routes edits through the live editor and save queue. The plugin runs no additional notebook service and needs no Node installation. Text read into Codex is available to its model; local storage is not a guarantee of offline AI processing.

Public-directory publication and remote/cloud access require a separate authenticated HTTPS deployment/relay design. This package targets local Windows Codex.
