# Notify 1.1.2 — bug and error-path audit

Reviewed the board editor, Mermaid import/conversion, static Reference, portable drawing/backup exports, autosave/recovery, browser storage, Tiptap editing and native command handlers. This is a corrective release; the drawing engine and existing visual language remain in place.

| Finding | Fix and verification |
| --- | --- |
| Damaged legacy recovery could hide a valid saved notebook; unsupported recovered metadata could reach automatic browser saving | Validate saved and recovered documents before adopting them. Preserve damaged legacy drafts separately; pin damaged journal records. A valid saved copy stays editable. Tests inject damaged/future recovery and trigger saving; unsupported primary documents remain untouched. |
| Browser saves replaced a newer copy from another window | Check the stored revision before writing, serialize browser saves through Web Locks when available, and retain the unsaved recovery draft on conflict. Two-window test verifies neither saved writing nor the current draft is lost. Without Web Locks, revision checking still applies, but simultaneous cross-process atomicity is not guaranteed. Desktop PostgreSQL already uses an atomic revision guard. |
| Missing clipboard threw before the Mermaid fallback; recovery-export failure was unhandled | Catch missing APIs, synchronous errors and rejected promises. Recovery errors are visible and retryable. Recovery uses a portable `.excalidraw` file that can be imported again. Tests inject missing clipboard and a failing download, then retry and parse the actual recovered drawing. |
| A file read could race with preview of the previous Mermaid source | Block preview/create until file reading completes; invalidate stale reads and conversions when source changes or the dialog closes. File-derived titles respect the same title limit. Delayed-read test verifies the prepared source. |
| A rejected board-dialog lazy import could remove the entire app | Contain it in a dismissible dialog error boundary; notes, folders and saving stay available. A failed canvas also retains exportable recovery. Injected chunk failures verify both paths. |
| Ordinary note paste/typing could exceed saving capacity after changing the editor | Validate document-changing transactions before committing them. Rejected content preserves accepted text, selection/history and Undo. Image insertion retains its existing preflight. An isolated editor test exercises ordinary paste, typing and Undo; existing native-size browser fixtures cover actual notebook capacity. |
| Malformed frame labels, grouping or appearance fields reached renderers | Validate these fields before adoption/import and in native saving. Both TypeScript and Rust checks reject malformed data rather than relying on a renderer crash. |
| Deleted board images remained in persisted file data and portable exports | Retain image files only for active image elements in saved/exported scenes. The live canvas keeps session Undo data; a real canvas delete/save/Undo test verifies space is freed and image data restored. |
| Failed UI mutations or backup serialization could escape event handlers | Guard app mutation callbacks, import completion, duplicate/checkpoint work and export serialization; retain the current item on failed creation/selection/archive. Failed sidebar moves announce failure without claiming a completed transfer. Native window actions and listener registration report failures instead of leaving rejected promises unhandled. Native failure messages are inspected in source; runtime window-command fault injection was not performed. |
| Narrow-window Reference could cover save errors and Retry | Keep the solid save-error strip above the floating Reference, wrap long messages and prevent the strip from shrinking away. Minimum-window dark/reduced-motion check verifies Retry is hit-testable; failed folder/delete actions retain their dialogs and avoid false success messages. |

No new animation or gesture controller was introduced. Error surfaces reuse the existing solid themed panels, Dialog focus trap, Escape/dismissal and status/alert semantics. Reopening tools does not overwrite a sketch. Tests retain the note editor and read-only Reference workflows, light/dark themes, minimum viewport and reduced motion.

Final validation counts, installer checksum and the exact executable's isolated PostgreSQL diagnostic are recorded in `../release/finalization-verification-1.1.2.json` and `../tests/verification.md`. Tests use disposable browser storage or an isolated diagnostic database; the installed app and personal notebook are not upgraded automatically.

Native canvas/clipboard/save-dialog interaction, IME composition, large-board WebView2 performance and actual paste into the user's Miro account remain manual checks. Previously documented advanced engine/hosted-service feature gaps remain in `boards-feature-audit.md`. Passing automated checks does not establish that every possible input or native interaction is bug-free.
