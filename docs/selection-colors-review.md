# Selected-text colors — 1.3.3

Right-click selected prose to open the existing solid ActionPopover at the pointer. Shift+F10, the Menu key and the Formatting palette button open it at the selected range. Three text and three background swatches appear initially; More colors expands both groups to nine. Each reset removes only its own mark. Selecting a choice returns focus to the same editor with the range intact; existing bold, lists and content survive. Escape, outside clicks, scrolling, a selection change or another app action menu dismisses the surface immediately. Read-only Reference and code/image context menus retain their existing behavior.

The popover reuses system typography, panel/line/hover/active/accent tokens, scaled 12px geometry and the shared floating shadow. It has no scrim or blur. Existing 100ms opacity entry remains its only motion, with an instant reduced-motion alternative. Expansion resizes the existing popover; ResizeObserver reclamps/flips it within the viewport. Invalid/missing event coordinates fall back to the selection geometry.

Tiptap marks store validated semantic color names rather than arbitrary inline styles. Light/dark foreground and background tokens adapt together, including the Reference rendering. The least-contrast pairing among the default and nine authored colors/backgrounds meets 4.5:1 in each theme. Color changes are Undo transactions over the captured selection and retain normal autosave. Backup import preserves only recognized mark attributes; styles, event handlers and invalid colors are stripped. No editor remount, animation dependency or per-frame React work is introduced.

Eight feature tests passed in development; all fourteen selected production checks passed (eight color tests and six existing menu-ownership regressions). Checks cover real pointer right-click, initial/expanded choices, independent resets, rich text preservation, keyboard access, Escape/focus return, editor identity, native-menu boundaries, browser save/reload, read-only Reference, portable imports, both themes, 850×600 bounds, reduced motion and contrast. Light/dark screenshots were visually inspected. TypeScript/Vite build and 21st review passed; the review's informational palette literals are intentional semantic token definitions. Catalog picker results were inspected; no catalog component was copied.

The broader production run also passed the applicable image and folder-copy behavior checks, but three older checks were inapplicable or stale: two image checks intercept/import development source modules and cannot run against built assets; the folder-copy keyboard helper clicks an already open trigger a second time and closes its menu. These failures are recorded separately from the passing color checks and were not hidden or changed as part of this feature.

Native WebView2 appearance and frame latency have not been visually measured. The native database diagnostic includes colored HTML in its save/restart equality check. Packaging and diagnostics use separate test data and do not install the app or modify the user's notebook.
